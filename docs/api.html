Harness

One small model answers typed questions about the current question and the last few turns of this chat. The call is SGLang POST /v1/systemone at http://127.0.0.1:30000 (MOIRA_HARNESS_URL). An empty value keeps the Ollama router, ollama:phi3. A local policy reads those answers and chooses replay or retrieve. The choice list stays at 26 options, including retrieve. The reasoner is the only model that writes the answer, and it stays the chat model.

TypeReturnsUsed for
Choicechoice, probabilities, confidenceWhich cached question this one matches, or retrieve.
Scorescore, probabilities, confidenceHow close the wording is, from different to the same question.
NoulA probability from 0 to 1Whether the intent is the same, and whether this turn continues the previous one.

Replay happens when the choice names a cached question, or when same-intent is at least 0.8, the score is “Same question,” and one cached question is the nearest choice. A failed call falls open to retrieve. A follow-up hangs under the previous question when the continuation probability is at least 0.8. A new topic hangs from a virtual root. Under each question the trie records the route, the ontology concept ids, and the answer. That trie is this chat only. The answer cache stays the memory shared across chats.

Jev model routing (MOIRA_MODEL_ROUTING=jev) and the Jev context harness (MOIRA_CONTEXT_HARNESS=jev) stay optional extras. They are separate from this call.

Context harness

Retrieval remains responsible for recall. The harness decides which retrieved concepts, neighbors, and web passages enter the prompt.

ClassBehaviorSource
PassthroughHarnessReturns the original shortlist. This is the default.context.py
JevContextHarnessUses Jev contextual scoring to filter and rerank. Shadow mode records the proposal while still returning the original shortlist.context.py
create_context_harness(name=None)Reads MOIRA_CONTEXT_HARNESS. jev starts in shadow mode unless MOIRA_CONTEXT_MODE=live.context.py
from moira.retrieval import JevContextHarness

harness = JevContextHarness(shadow=True, min_relevance=0.2)
answer = workspace.ask(question, harness=harness)
print(workspace.last_context_selection.metrics())

Jev is optional: uv sync --extra jev and JEV_API_KEY. Query text, concept labels, and web snippets are sent to TypeSafe. If the key is missing or Jev fails, the harness fails open and returns the original shortlist.

Model routing

create_model_router() returns a router when MOIRA_MODEL_ROUTING=jev. It asks one choice question, then Agent.invoke uses the selected model for that run.

RouteCriterionModel
localShort lookups, extraction, and questions answerable from retrieved ontology context.MOIRA_ROUTE_LOCAL, default ollama:phi3
standardNormal ontology question answering and relation lookup.MOIRA_ROUTE_STANDARD, default LLM_MODEL
carefulAlignment disputes, conflicts, refinement, or multi-ontology reasoning.MOIRA_ROUTE_CAREFUL, default LLM_MODEL

The model_route step and the llm_invoke step store name, model_name, probabilities, confidence, fail_open, and error. The same payload is emitted as model.routed for Ontology-of-Thought. If Jev is unavailable, the run fails open to the current model.

Tool-risk gating

create_tool_gate() returns a gate when MOIRA_TOOL_GATE=jev. It runs after tool.parsed and before tool execution. The default gated tools are search_term_context and search_knowledge_graph. Override them with MOIRA_GATED_TOOLS. ontology_term_info is not gated.

Jev returns the probability that the call is unsafe. A value at or above MOIRA_TOOL_RISK_THRESHOLD (default 0.5) becomes the tool result:

{"blocked": true, "tool_name": "search_term_context", "reason": "...", "risk": 0.92}

The tool function is not called. The tool_execute step status is blocked, and Ontology-of-Thought receives tool.blocked. Arguments are passed through redact before the request. Query text and those redacted arguments are still sent to TypeSafe. When the gate is enabled and Jev cannot decide, that gated call fails closed. A disabled gate leaves every tool call unchanged.
